# 車両管理アプリ 市場調査・UX分析レポート

> 作成日: 2026-07-20
> プロジェクト: Stylish-MyCars (Android / Kotlin / Jetpack Compose)
> 目的: 既存アプリの不満点分析と差別化ポイントの特定

## 1. 既存アプリのよくある不満点・改善点

### 1.1 主要な競合アプリ一覧

| アプリ名 | 対応OS | 主な機能 | 価格モデル |
|---------|--------|---------|-----------|
| CarForm (カーフォーム) | iOS/Android | 整備記録、費用管理、リマインダー | 無料+広告/有料 |
| Drivvo | iOS/Android | 燃費管理、費用追跡、複数台 | 無料+広告/有料 |
| Fuelio | Android | 燃費記録、ルート追跡 | 無料(広告あり) |
| aCar | Android | 車両管理、費用、燃費 | 無料/有料 |
| Car Minder | iOS | メンテナンス記録、リマインダー | 有料 |
| くるま管理 (国内) | iOS/Android | 車検・税金管理 | 無料+広告 |

### 1.2 アプリストアレビューから読み取れる不満パターン

#### UI/UXに関する不満（頻出度: ★★★★★）

- **「UIが古臭い」「2010年代のデザイン」** — 特にaCar、FuelioなどのAndroidアプリで顕著。Material Design未対応、または古いMaterial 1のデザイン
- **「情報が多すぎて何を見ればいいかわからない」** — ダッシュボードの設計が不十分。全情報を1画面に詰め込む傾向
- **「広告が画面の30%を占める」** — 無料版の広告がUXを著しく損なう。特に記録入力直後に全画面広告が表示されるケース
- **「ダークモード非対応」** — 車内での夜間使用時に眩しい
- **「日本語翻訳が機械的で不自然」** — 海外製アプリのローカライズ品質問題

#### 入力の手間に関する不満（頻出度: ★★★★★）

- **「給油のたびに5項目も入力するのが面倒で続かない」** — 継続利用の最大の障壁
- **「ODOメーターを手入力するのが面倒。写真から読み取ってほしい」** — OCR要望は非常に多い
- **「整備記録の入力項目が多すぎる。もっとシンプルにしたい」**
- **「音声で入力したい（運転中・作業中で手が塞がっている）」**
- **「レシートを撮影するだけで自動入力してほしい」**

#### 通知・リマインダーに関する不満（頻出度: ★★★★☆）

- **「通知が来ない、または遅れて来る」** — バックグラウンド制限（AndroidのDozeモード、メーカー独自制限）が原因
- **「通知が多すぎて全部無視するようになった」** — 通知の優先度設計の欠如
- **「車検の3ヶ月前から毎週通知が来る。うるさい」** — 通知頻度の細かな制御ができない
- **「通知をタップしても該当画面に遷移しない」** — Deep Link未実装

#### データ管理に関する不満（頻出度: ★★★★☆）

- **「エクスポート機能がない。データがアプリ内に閉じ込められている」**
- **「アプリを削除したら全データが消えた。バックアップがなかった」**
- **「機種変更でデータが引き継げない」**
- **「CSV出力できるが、項目が足りなくて整備記録として使えない」**
- **「クラウド同期がない。タブレットとスマホで使い分けたい」**
- **「サービス終了でデータが全部消えた」** — 過去に複数の車両管理アプリがサービス終了

#### 日本特有の要件への不満（頻出度: ★★★★☆）

- **「車検の管理はできるが、自賠責保険の満期管理ができない」**
- **「自動車税の納付時期リマインダーがない」**
- **「軽自動車と普通車で税額が違うのに区別できない」**
- **「整備記録簿（法定12ヶ月・24ヶ月点検）のフォーマットに対応していない」**
- **「エコカー減税・グリーン化特例に対応していない」**
- **「リコール情報の通知が欲しい」**

#### 複数台管理に関する不満（頻出度: ★★★☆☆）

- **「2台目以降の管理が非常にやりにくい」**
- **「車両ごとの費用集計ができない」**
- **「家族の車をまとめて管理したいが、ユーザー単位でしか管理できない」**
- **「バイクも管理したいが車両種別が車しかない」**

### 1.3 不満点の優先度マトリクス

```
影響度 高 │ 入力の手間        │ データ消失リスク
          │ 通知の信頼性      │ 日本要件への対応
          │───────────────────│──────────────────
          │ UIの古さ          │ 複数台管理
影響度 中 │ 広告の多さ        │ オフライン非対応
          │ 写真管理の不便    │ エクスポート制限
          │───────────────────│──────────────────
          │ ダークモード      │ OBD-II連携
影響度 低 │ ウィジェット      │ AI予測
          └───────────────────┴──────────────────
            頻出度 高            頻出度 低
```

## 2. UX/UIのベストプラクティス

### 2.1 ダッシュボード設計

#### 原則: 「3秒ルール」— アプリを開いて3秒で最も重要な情報がわかること

**推奨ダッシュボード構成:**

```
┌─────────────────────────────────────────┐
│  [車両切替タブ]  🚗 プリウス  │ 🏍 NINJA │
├─────────────────────────────────────────┤
│                                         │
│  ⚠️ 要注意カード（最大2件）              │
│  ┌─────────────────────────────────┐    │
│  │ 🔴 車検まであと45日 (2026/09/03)│    │
│  └─────────────────────────────────┘    │
│  ┌─────────────────────────────────┐    │
│  │ 🟡 次回オイル交換: 500km後       │    │
│  └─────────────────────────────────┘    │
│                                         │
│  📊 今月の費用サマリー                   │
│  ┌──────────┬──────────┐               │
│  │ ¥12,340  │ 先月比-8% │               │
│  └──────────┴──────────┘               │
│                                         │
│  🚗 車両ステータス                       │
│  ┌─────────────────────────────────┐    │
│  │ ODO: 45,230km                   │    │
│  │ 燃費: 18.2km/L (▲0.3)          │    │
│  │ 次回給油目安: 約320km後          │    │
│  └─────────────────────────────────┘    │
│                                         │
│  📋 最近の記録（最新3件）                │
│  • 07/15 給油 32.5L ¥5,688            │
│  • 07/01 オイル交換 ¥4,200             │
│  • 06/20 洗車                          │
│                                         │
│  [+ クイック記録]  (FAB)                │
└─────────────────────────────────────────┘
```

**設計原則:**
- **緊急度ベースのソート**: 期限が近いものほど上に表示
- **シグナル vs ノイズ**: 異常・期限接近のみ強調。通常状態は控えめに
- **プログレッシブ・ディスクロージャー**: 概要→タップで詳細
- **色覚多様性対応**: 色だけでなくアイコン・テキストでも状態を表現（赤/黄/緑の信号機方式＋アイコン）

### 2.2 入力の簡素化

#### 最優先: 給油記録の入力を10秒以内に

| 手法 | 効果 | 実装難易度 | 優先度 |
|------|------|-----------|--------|
| ODOメーター写真→OCR | 手入力不要、誤入力防止 | 中（ML Kit） | ★★★ |
| レシート写真→OCR | 金額・量・日付を自動入力 | 中（ML Kit + パース） | ★★★ |
| ワンタップ給油記録 | 前回値をプリセット | 低 | ★★★ |
| 音声入力 | 手が塞がっている時に有効 | 低（SpeechRecognizer） | ★★☆ |
| ウィジェットからのクイック入力 | アプリ起動不要 | 中 | ★★☆ |
| OBD-II自動取得 | 完全自動化 | 高（BLE + ELM327） | ★☆☆ |

#### OCR実装のベストプラクティス:
- **カメラ起動→撮影→認識→確認→保存** のフローを3タップ以内で
- 認識結果は必ずユーザーが確認・修正できるUIにする（過信しない）
- オフラインで動作するML Kit Text Recognition v2を推奨
- ODOメーターは数字のみの認識で精度が高い（7桁程度）

### 2.3 通知・リマインダーの設計

#### 通知の階層設計

| 優先度 | 例 | 通知チャネル | 頻度 |
|--------|-----|-------------|------|
| **緊急** | 車検まで30日以内、リコール | 通知 + 通知ドット | 1回/日 |
| **重要** | 車検まで90日、自賠責満期、オイル交換目安 | 通知 | 1回/週 |
| **参考** | 月次費用サマリー、燃費レポート | 通知（まとめ） | 1回/月 |
| **サイレント** | バックアップ完了、データ同期 | 通知なし（アプリ内のみ） | 都度 |

#### 通知設計の原則:
- **Android通知チャネルを必ず分離**（ユーザーがチャネル単位で制御可能に）
- **スヌーズ機能**: 「1週間後に再通知」を通知アクションから直接
- **エスカレーション**: 期限が近づくにつれ頻度を上げる（が、最大1日1回）
- **通知タップ→該当画面にDeep Link**
- **WorkManager + 正確なアラームの併用**: Dozeモード対策
- **通知のまとめ**: 複数車両の通知を1つにグループ化

### 2.4 視覚的な車両状態の表示

- **車両イラスト/アイコン + ステータスバッジ**: 一目で状態がわかる
- **タイムラインビュー**: 整備履歴を時系列で表示（車両の「カルテ」）
- **費用の可視化**: 月次/年次の費用推移グラフ、カテゴリ別円グラフ
- **燃費トレンド**: 折れ線グラフで悪化傾向を視覚化（異常検知の入口）
- **部品ごとの交換サイクル表示**: 「あと○kmで交換目安」をプログレスバーで

## 3. 差別化の方向性

### 3.1 日本市場特化機能（最大の差別化ポイント）

#### 3.1.1 車検・法定点検管理

```
日本の車検制度:
├── 新車: 初回3年
├── 以降: 2年ごと
├── 軽自動車: 同上（2024年改正後も2年）
├── 法定12ヶ月点検（1年ごと）
├── 法定24ヶ月点検（車検時）
└── 整備記録簿の保存義務（道路運送車両法）
```

**実装すべき機能:**
- 初度登録年月から車検満了日を自動計算
- 車検費用の概算表示（車両重量・種別別）
- 法定12ヶ月・24ヶ月点検のチェックリスト（国土交通省の点検項目に準拠）
- 整備記録簿のPDF出力（法定様式に準拠）— **法的効力を持つ記録として**
- 車検見積もりの比較メモ機能

#### 3.1.2 税金管理

| 税目 | 課税時期 | 管理機能 |
|------|---------|---------|
| 自動車税（種別割） | 4月1日（5月納付） | 納付期限リマインダー、税額計算 |
| 自動車重量税 | 車検時 | 車検費用に含めて管理 |
| 軽自動車税 | 4月1日（5月納付） | 同上 |
| 環境性能割 | 取得時 | 取得時費用に記録 |

- **グリーン化特例・エコカー減税の適用判定**（初度登録年・燃費基準から）
- 排気量・車両重量からの税額自動計算
- 納付済みフラグ管理

#### 3.1.3 自賠責保険管理

- 満期日リマインダー（車検と連動）
- 保険料の記録
- 保険会社・証券番号の保管
- **車検と自賠責の満期が異なる場合の警告**（中古車購入時によくある）

#### 3.1.4 日本特有の追加機能

- **リコール情報**: 国土交通省のリコール届出情報との照合（メーカー・型式・製造期間）
- **駐車場証明書管理**: 車庫証明の有効期限
- **ETC車載器管理**: セットアップ情報、有効期限
- **任意保険管理**: 満期日、保険料、等級、補償内容の記録
- **JAF/ロードサービス**: 会員番号・連絡先のクイックアクセス
- **ガソリン価格**: 地域別の価格推移（API連携 or 手入力）

### 3.2 AI/MLの活用

| 機能 | 説明 | 実装アプローチ | 優先度 |
|------|------|---------------|--------|
| ODOメーターOCR | 写真から走行距離を認識 | ML Kit Text Recognition | ★★★ |
| レシートOCR | 給油レシートから金額・量を抽出 | ML Kit + カスタムパース | ★★★ |
| メンテナンス予測 | 走行距離・期間から次回整備時期を予測 | ルールベース → 統計モデル | ★★☆ |
| 燃費異常検知 | 燃費の急激な悪化を警告 | 移動平均 + 標準偏差 | ★★☆ |
| 費用予測 | 年間維持費の予測 | 過去データの線形回帰 | ★☆☆ |
| 音声アシスタント | 「給油32リットル5000円」で記録 | Speech-to-Text + NLU | ★☆☆ |

### 3.3 OBD-II連携（中長期）

- **ELM327互換BLEアダプタ**経由で車両診断
- 取得可能データ: 走行距離、エンジン回転数、冷却水温、故障コード(DTC)
- **MVPでは非推奨**（対応車両のばらつき、BLE接続の不安定さ、ユーザーの技術的ハードル）
- 将来的に「車両の健康診断」機能として差別化に有効

### 3.4 家族・世帯での共有機能

- **世帯単位での車両管理**: 1アカウントで複数車両・複数ドライバー
- **共有メモ**: 「来月車検だよ」「オイル交換した？」
- **費用の按分**: 家族で使う車の費用を分担
- **権限管理**: 子供には記録の閲覧のみ、親は編集可能
- **実装**: Firebase / Supabase のリアルタイムDB、またはローカル＋共有ストレージ

### 3.5 整備工場との連携（長期ビジョン）

- 整備記録のQRコード共有（整備工場がスキャンして記録追加）
- 見積書の写真添付・比較
- 整備工場のお気に入り登録・メモ
- **将来的に**: 整備工場向けアプリとのデータ連携API

### 3.6 車両の資産価値トラッキング

- 購入価格・諸費用の記録
- 走行距離・年式からのおおよその残価推定
- 整備履歴の充実度 → 査定時のアピール材料として
- **売却時のサマリーレポート出力**（整備記録簿 + 費用総額）

## 4. 技術的考慮事項

### 4.1 オフラインファースト設計（最重要）

**理由**: 駐車場・ガレージ・山間部など電波が届かない場所で使うことが多い

```
アーキテクチャ推奨:
┌──────────────┐
│   UI Layer   │  Jetpack Compose + Material 3
├──────────────┤
│  ViewModel   │  StateFlow / UiState
├──────────────┤
│  Repository  │  Single Source of Truth
├──────┬───────┤
│ Room │ Remote│  Room = ローカルDB（常に書き込み先）
│(SQLite)│(API)│  Remote = 同期専用（オンライン時のみ）
└──────┴───────┘
```

- **Room**をプライマリデータストアとして使用
- 全操作はまずローカルに書き込み、バックグラウンドで同期
- 競合解決: Last-Write-Wins + 手動マージオプション
- **WorkManager**でバックグラウンド同期

### 4.2 データのバックアップ・同期

| 方式 | 長所 | 短所 | 推奨度 |
|------|------|------|--------|
| ローカルエクスポート (JSON/CSV) | シンプル、オフライン可、ユーザーが制御 | 手動、同期不可 | ★★★（必須） |
| Google Drive バックアップ | ユーザーに馴染み、無料枠十分 | API制約、認証必要 | ★★☆ |
| Firebase/Supabase同期 | リアルタイム、複数デバイス | サーバー依存、コスト | ★★☆（将来） |
| Auto Backup (Android) | 自動、OS標準 | 容量制限(25MB)、復元が不安定 | ★☆☆（補助） |

**MVPでの推奨**: ローカルエクスポート（JSON + CSV）を最優先で実装。データポータビリティの保証は信頼に直結する。

### 4.3 プライバシー

- **位置情報は取得しない**（MVPでは不要。ルート追跡は将来機能）
- 車両情報（ナンバー、車台番号）は暗号化して保存（EncryptedSharedPreferences / SQLCipher）
- 写真はアプリのプライベートストレージに保存（外部ストレージ不可）
- **プライバシーポリシー**: 収集するデータ、用途を明記
- 広告SDKは入れない（またはオプトイン式）— 車両情報はプライバシー感度が高い

### 4.4 写真・書類のOCR

- **ML Kit Text Recognition v2**（オフライン対応、無料）
- 日本語対応: かな・漢字の認識も可能（レシートOCRに有効）
- ODOメーター: 数字のみの認識で高精度（`[0-9]` のフィルタリング）
- 車検証OCR: 定型フォーマットなので項目ごとのパースが容易
- **CameraX** + ML Kit の組み合わせでリアルタイムプレビュー認識も可能

### 4.5 ウィジェット・通知の活用

- **Glance (Jetpack Compose for Widgets)** でホーム画面ウィジェット
  - 次回の整備予定日表示
  - 今月の費用合計
  - クイック記録ボタン
- **通知チャネル設計**（前述 2.3 参照）
- **クイック設定タイル**: 通知シェードからクイック記録

### 4.6 推奨技術スタック（本プロジェクト向け）

| カテゴリ | 技術 | 理由 |
|---------|------|------|
| UI | Jetpack Compose + Material 3 | 既に採用済み。モダンなUI |
| ローカルDB | Room | オフラインファーストの基盤 |
| 非同期 | Kotlin Coroutines + Flow | Composeとの親和性 |
| DI | Hilt | Android標準のDI |
| 画像取得 | CameraX | ML Kitとの統合が容易 |
| OCR | ML Kit Text Recognition v2 | オフライン対応、無料 |
| バックグラウンド | WorkManager | 通知・同期の信頼性 |
| ナビゲーション | Navigation Compose | 型安全なナビゲーション |
| 写真管理 | Coil | Compose対応の画像読み込み |
| グラフ | Vico / Compose Canvas | 費用・燃費の可視化 |
| バックアップ | SAF (Storage Access Framework) | ユーザーが保存先を選択 |

## 5. ターゲットユーザーのペルソナ

### 5.1 ペルソナA: 車を1台だけ持つ一般ユーザー（メインターゲット）

```
名前: 田中 健一（42歳）
職業: 会社員（営業）
車両: トヨタ カローラ（2022年式、普通車）
ITリテラシー: 中（スマホは使うがアプリに詳しくない）

課題:
- 車検の時期をいつも忘れて焦る
- 整備記録が紙で散らばっている
- 年間維持費がいくらかわからない
- アプリ入力が面倒で続かない

求めるもの:
```

### 6.4 差別化の核心 — 「日本の車オーナーのための、最も信頼できる車両管理アプリ」

**既存アプリとの差別化ポイントまとめ:**

1. **日本制度への完全対応**: 車検・自賠責・自動車税・法定点検をワンストップで管理。海外製アプリでは絶対にできない
2. **データポータビリティの保証**: エクスポート自由、オフライン動作、サービス終了してもデータは残る。ユーザーのデータを人質にしない
3. **入力の最小化**: OCR、ワンタップ、ウィジェットで「記録する面倒」を極限まで減らす
4. **プライバシー重視**: 広告なし（または最小限）、位置情報不要、車両情報は暗号化
5. **モダンなUI/UX**: Material 3、ダークモード、3秒で状況がわかるダッシュボード
6. **法定整備記録簿のデジタル化**: 法的効力を持つ記録をアプリで管理・出力できる

## 7. 参考情報

### 7.1 日本の車両関連制度

- **車検（自動車検査登録制度）**: 道路運送車両法第58条。新車3年、以降2年ごと
- **法定12ヶ月点検**: 道路運送車両法第48条。1年ごとの定期点検
- **法定24ヶ月点検**: 同上。車検時の点検
- **整備記録簿**: 道路運送車両法第49条。記録・保存義務あり
- **自動車税**: 地方税法。4月1日現在の所有者に課税。5月納付
- **自賠責保険**: 自動車損害賠償保障法。車検期間と連動
- **リコール制度**: 道路運送車両法第63条の2。国土交通省に届出

### 7.2 競合の弱点まとめ（攻略ポイント）

| 競合の弱点 | 我々の強み |
|-----------|-----------|
| 海外製で日本制度に未対応 | 車検・税金・法定点検に完全対応 |
| 広告が多くUXを損なう | 広告なし or 最小限 |
| データがロックイン | 自由なエクスポート |
| UIが古い | Material 3 + Compose |
| 入力が面倒 | OCR + ワンタップ |
| オフライン非対応 | オフラインファースト |
| 通知が信頼できない | チャネル設計 + WorkManager |
